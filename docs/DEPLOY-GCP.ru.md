# Запуск на Google Cloud: первая проверка в настоящем Telegram

Эта инструкция для владельца проекта: всё делается мышкой в браузере и копированием готовых команд. Опыт программирования не нужен. Займёт 2–3 часа, из них час-полтора компьютер работает сам.

Что получится: семейная кулинарная книга работает на одном небольшом сервере Google Cloud, открывается в Telegram как Mini App, бот присылает сообщения по таймерам. Фото хранятся в Google Cloud Storage, база данных каждую ночь сохраняется в отдельное хранилище.

> **Я (Claude) ничего не разворачиваю и не имею доступа к вашему аккаунту Google.** Все шаги ниже делаете вы. Если что-то не получилось, пришлите мне текст ошибки или снимок экрана (сначала проверьте, что на нём нет токена или ключа, см. раздел 1).

Названия кнопок в консоли Google иногда меняются. Если кнопка называется чуть иначе, ищите похожую по смыслу.

## 1. Главное правило: секреты

В этой инструкции встретятся **секреты**: значения, с которыми чужой человек может управлять вашим ботом или читать ваши данные.

| Секрет                                          | Где появится                                     |
| ----------------------------------------------- | ------------------------------------------------ |
| Токен бота (`BOT_TOKEN`, вида `1234567890:AA…`) | BotFather в Telegram                             |
| Ключ хранилища фото (Access key и Secret)       | консоль Google Cloud                             |
| Токен DuckDNS                                   | сайт duckdns.org                                 |
| Пароли базы данных                              | создаются на сервере сами, вы их даже не увидите |

**Правила:**

- Секреты хранятся **только** в файле `.env` на сервере. Вы создаёте его сами (раздел 9).
- **Никогда** не вставляйте секрет в чат (в том числе со мной), на GitHub, в письмо или в заметки.
- Перед тем как отправить кому-то снимок экрана, проверьте, что на нём нет секрета. Если есть, закрасьте его или переснимите.
- В репозитории лежит только `deploy/gcp/.env.example` с заглушками `CHANGE_ME`. Приложение **откажется запускаться**, пока хоть одна заглушка не заменена или пароль слишком простой. Это сделано специально.

**Если секрет всё-таки попал не туда:**

- **Токен бота:** в BotFather отправьте `/revoke`, выберите бота. Старый токен перестанет работать, новый впишите в `.env` на сервере.
- **Ключ хранилища:** в консоли Google удалите этот ключ (раздел 5.3) и создайте новый.
- **Токен DuckDNS:** на duckdns.org нажмите «recreate token».

После замены перезапустите приложение: `docker compose up -d`.

## 2. Оповещения о расходах (до всего остального)

Сначала настроим письма о расходах. Тогда вы узнаете о тратах раньше, чем кредит закончится.

1. Откройте <https://console.cloud.google.com/billing> и войдите в свой аккаунт Google.
2. Выберите свой платёжный аккаунт (Billing account).
3. Слева нажмите **Budgets & alerts** (Бюджеты и оповещения), затем **Create budget**.
4. **Name:** `Кулинарная книга 10 USD`.
5. **Scope:** оставьте все проекты и все сервисы. Нажмите **Next**.
6. **Amount:**
   - Budget type: **Specified amount**;
   - Target amount: **10** (USD).
   - Нажмите **Next**.
7. **Actions → Alert threshold rules.** Оставьте две строки (лишние удалите кнопкой корзины):
   - **50 %** (это 5 USD), Trigger on: **Actual**;
   - **100 %** (это 10 USD), Trigger on: **Actual**.
8. Поставьте галочку **Email alerts to billing admins and users**.
9. Нажмите **Finish**.

> Бюджет **только присылает письма, он не останавливает расходы**. Если пришло письмо о 5 USD раньше середины месяца, загляните в раздел 12 («Остановить сервер»).

## 3. Регион и сколько это стоит

У вас около 10 USD кредита в месяц. Для семейной книги подходят два варианта.

|                                        | **A. США, бесплатный уровень**                     | **B. Европа**                                               |
| -------------------------------------- | -------------------------------------------------- | ----------------------------------------------------------- |
| Регион                                 | `us-east1` (Южная Каролина)                        | `europe-west4` (Нидерланды) или `europe-north1` (Финляндия) |
| Сервер e2-micro (1 ГБ памяти)          | **0 USD** (Free Tier: один такой сервер бесплатно) | около **6,7 USD**                                           |
| Внешний IP-адрес (пока сервер включён) | около **3,65 USD**                                 | около **3,65 USD**                                          |
| Диск 20 ГБ (Standard)                  | 0 USD (бесплатно до 30 ГБ)                         | около **0,9 USD**                                           |
| Хранилище фото и копий (1–2 ГБ)        | 0 USD (бесплатно до 5 ГБ)                          | около **0,05 USD**                                          |
| Исходящий трафик (немного фото)        | около 0–0,3 USD                                    | около 0,1–0,3 USD                                           |
| **Итого в месяц**                      | **около 4 USD**                                    | **около 11–12 USD**                                         |
| Задержка из Европы                     | около 90–120 мс на запрос                          | около 10–40 мс                                              |
| Где хранятся данные семьи              | в США                                              | в ЕС                                                        |

Следующий размер сервера, **e2-small** (2 ГБ памяти), стоит около 12–13,5 USD в месяц. С IP-адресом и диском выходит около **16 USD (США)** или **18–19 USD (Европа)**. Это на 6–12 USD в месяц больше, чем e2-micro.

> **Цены примерные (октябрь 2026), проверьте их на страницах Google:**
>
> - [цены серверов](https://cloud.google.com/compute/vm-instance-pricing);
> - [IP-адреса и трафик](https://cloud.google.com/vpc/network-pricing);
> - [хранилище](https://cloud.google.com/storage/pricing);
> - [бесплатный уровень](https://cloud.google.com/free/docs/free-cloud-features#compute).
>
> Бесплатный сервер e2-micro бывает только в регионах `us-west1`, `us-central1` и `us-east1`. Внешний IPv4-адрес, насколько мне известно, оплачивается и на бесплатном уровне; это тоже стоит проверить.

**Моя рекомендация для первой проверки: вариант A (`us-east1`).**

- Это самый близкий к Европе из бесплатных регионов, и всё укладывается в кредит с запасом.
- Задержку около 0,1 секунды в Mini App почти не заметно.
- Сообщения бота это не замедляет: таймеры работают на сервере.

Если важно, чтобы данные семьи хранились в ЕС, выбирайте B и следите за письмом о 10 USD. Переехать потом можно: перенести резервную копию базы на новый сервер (раздел 11).

**Хватит ли 1 ГБ памяти?** Я измерил это на той же сборке приложения, которая пойдёт на сервер.

- **Работа:** да, хватает. Всё приложение в покое занимает около 110 МБ. Под нагрузкой пик был около 380 МБ: 5 человек одновременно, 4 больших фото с телефона сразу, разбор рецептов, таймеры. Linux, Docker и служебные программы Google займут ещё примерно 250–300 МБ (оценка, на настоящем сервере я не измерял). Остаётся запас.
- **Сборка** при установке и обновлениях: самый тяжёлый шаг берёт около 520 МБ. С файлом подкачки (раздел 9.2) она проходит, но медленно: 15–30 минут.
- **Когда брать e2-small:** если обновления идут слишком долго или сервер «задумывается» (раздел 13).

Для семьи до 10 человек 1 ГБ достаточно.

## 5. Хранилища: фото и резервные копии

Нужны два «ведра» (bucket) в Cloud Storage: одно для фото, второе для ночных копий базы данных.

### 5.1. Ведро для фото

1. Откройте <https://console.cloud.google.com/storage/browser> и нажмите **Create**.
2. **Name:** уникальное имя из маленьких латинских букв, цифр и дефисов, например `family-cookbook-photos-4821` (цифры любые). **Запишите его**: это `S3_BUCKET`.
3. **Location type:** **Region**, тот же регион, что вы выбрали в разделе 3 (например, `us-east1`).
4. **Storage class:** **Standard**.
5. **Access control:**
   - поставьте галочку **Enforce public access prevention on this bucket**: фото открываются только по временным ссылкам приложения;
   - выберите **Uniform**.
6. **Protection:** оставьте как есть. Нажмите **Create**. Если спросят про public access prevention, подтвердите.

### 5.2. Служебный аккаунт для фото

Приложению нужен свой «пользователь» с доступом только к ведру фото.

1. Откройте <https://console.cloud.google.com/iam-admin/serviceaccounts> и нажмите **Create service account**.
2. **Name:** `cookbook-photos`. Нажмите **Create and continue**.
3. На шаге **Grant this service account access to project** ничего не выбирайте, нажмите **Done**.
4. Вернитесь в ведро фото (Cloud Storage → ваше ведро), вкладка **Permissions** → **Grant access**.
5. **New principals:** начните вводить `cookbook-photos` и выберите аккаунт из списка.
6. **Role:** **Storage Object User** (чтение, запись и удаление файлов, но не настройки ведра). Нажмите **Save**.

### 5.3. Ключ хранилища (HMAC)

Это секрет. Создавайте его, **когда на сервере уже открыт файл `.env`** (раздел 9.5): так его можно сразу вставить туда, никуда больше не сохраняя.

1. Откройте <https://console.cloud.google.com/storage/settings>, вкладка **Interoperability**.
2. В разделе **Access keys for service accounts** нажмите **Create a key for a service account**.
3. Выберите `cookbook-photos` → **Create key**.
4. Появятся **Access key** (это `S3_ACCESS_KEY`) и **Secret** (это `S3_SECRET_KEY`). **Secret показывается один раз.** Скопируйте оба значения прямо в `.env` на сервере (раздел 9.5).
5. Если Secret потерялся, удалите этот ключ и создайте новый.

### 5.4. Ведро для резервных копий

1. Cloud Storage → **Create**.
2. **Name:** например `family-cookbook-backups-4821`. **Запишите**: это `BACKUP_BUCKET`.
3. Тот же регион, **Standard**, **Enforce public access prevention**, **Uniform**. Нажмите **Create**.
4. Откройте это ведро, вкладка **Lifecycle** → **Add a rule**:
   - Action: **Delete object**;
   - Condition: **Age** = **30** дней;
   - нажмите **Create**.

   Старые копии будут удаляться сами, хранятся последние 30.

Доступ к этому ведру выдадим серверу в разделе 6.

## 6. Сервер (виртуальная машина)

### 6.1. Служебный аккаунт сервера

1. <https://console.cloud.google.com/iam-admin/serviceaccounts> → **Create service account**.
2. **Name:** `cookbook-vm` → **Create and continue** → без ролей → **Done**.
3. Откройте ведро резервных копий → **Permissions** → **Grant access**:
   - **New principals:** `cookbook-vm`;
   - **Role:** **Storage Object Creator**;
   - нажмите **Add another role**, выберите **Storage Object Viewer**;
   - нажмите **Save**.

Так сервер сможет класть копии и читать их для проверки, но **не сможет их удалить**. Даже если кто-то захватит сервер, старые копии останутся.

### 6.2. Создание сервера

1. Откройте <https://console.cloud.google.com/compute/instancesAdd>.
2. **Name:** `cookbook`.
3. **Region:** из раздела 3 (например, `us-east1`). **Zone:** любая.
4. **Machine configuration:** серия **E2**, тип **e2-micro** (или **e2-small**, если решили сразу брать побольше).
5. **OS and storage** (или **Boot disk**) → **Change**:
   - Operating system: **Debian**;
   - Version: **Debian GNU/Linux 12 (bookworm)**;
   - Boot disk type: **Standard persistent disk**;
   - Size: **20** GB;
   - нажмите **Select**.
6. **Security** (или **Identity and API access**) → Service account: **cookbook-vm**.
7. **Networking** → Firewall: поставьте обе галочки, **Allow HTTP traffic** и **Allow HTTPS traffic**. Внешний адрес (External IPv4) оставьте **Ephemeral**: он бесплатный, когда сервер выключен, а адрес в DuckDNS будет обновляться сам.
8. Справа видна примерная цена в месяц. Сверьте её с разделом 3. Нажмите **Create**.
9. Через минуту сервер появится в списке. **Запишите External IP** (вида `34.75.12.34`).

## 7. Бесплатный адрес с HTTPS: DuckDNS

Telegram открывает Mini App только по адресу `https://`. Нужно имя, которое указывает на ваш сервер. DuckDNS даёт его бесплатно, а Caddy (часть приложения) сам получит для него сертификат Let's Encrypt и будет его продлевать.

1. Откройте <https://www.duckdns.org> и войдите через Google или GitHub.
2. В поле **sub domain** введите имя, например `family-cookbook-4821`, и нажмите **add domain**.
3. В строке этого имени, в поле **current ip**, вставьте External IP сервера (раздел 6.2) и нажмите **update ip**.
4. Ваш адрес: `family-cookbook-4821.duckdns.org`. Это `DOMAIN`, а `family-cookbook-4821` — это `DUCKDNS_SUBDOMAIN`.
5. Вверху страницы есть **token**. Это секрет `DUCKDNS_TOKEN`, его вы скопируете в `.env` на сервере (раздел 9.5).

Если сервер выключить и включить, Google может дать ему новый адрес. Программа на сервере сама сообщит его DuckDNS при запуске и затем каждые 5 минут.

> DuckDNS — бесплатный сервис энтузиастов: изредка он недоступен. Для долгой жизни приложения лучше купить свой домен (около 10–15 USD в год). Это можно сделать позже, приложение от этого не меняется.

## 8. Бот и Mini App в BotFather

В Telegram откройте [@BotFather](https://t.me/BotFather).

1. **Бот.** Отправьте `/newbot`.
   - Имя, например `Семейная кулинарная книга`.
   - Username, заканчивается на `bot`, например `family_cookbook_4821_bot`. Это `BOT_USERNAME` (без `@`).
   - BotFather пришлёт **токен**. Это секрет `BOT_TOKEN`. Не пересылайте это сообщение; позже скопируете токен прямо в `.env` на сервере.
2. **Mini App.** Отправьте `/newapp` и выберите своего бота.
   - Title: `Кулинарная книга`; Description: пара слов.
   - Photo: картинка 640×360. Подойдёт любая, например фото блюда.
   - GIF: отправьте `/empty`.
   - **Web App URL:** `https://family-cookbook-4821.duckdns.org` (ваш `DOMAIN` с `https://`).
   - **Short name:** например `cook`. Это `MINI_APP_SHORT_NAME`.

   Ссылка на приложение будет `https://t.me/family_cookbook_4821_bot/cook`.

3. **Кнопка в чате с ботом** (по желанию). Отправьте `/mybots` → ваш бот → **Bot Settings** → **Menu Button** → **Configure menu button**. Пришлите тот же адрес `https://…duckdns.org` и название кнопки `Открыть книгу`.

Позже адрес Mini App можно поменять так: `/mybots` → бот → **Bot Settings** → **Configure Mini App** (или `/myapps` → приложение → **Edit Web App URL**).

## 9. Установка на сервер

### 9.1. Терминал сервера

1. Откройте <https://console.cloud.google.com/compute/instances>.
2. В строке `cookbook` нажмите **SSH**. Откроется окно с чёрным терминалом: это сервер.
3. Команды ниже копируйте **блоками** (кнопка копирования справа от блока) и вставляйте в это окно:
   - правой кнопкой мыши → **Paste**, или **Ctrl+Shift+V**;
   - затем нажмите **Enter**.

### 9.2. Файл подкачки (2 ГБ)

Подкачка нужна, чтобы маленькому серверу хватило памяти при сборке.

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

В строке `Swap:` должно быть около `2.0Gi`.

### 9.3. Docker и git

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo apt-get install -y git
sudo usermod -aG docker "$USER"
```

Теперь **закройте окно SSH и откройте его снова** (кнопка **SSH**). Без этого следующая команда не сработает. Проверка:

```bash
docker version --format 'Docker {{.Server.Version}}'
```

### 9.4. Код приложения

Если репозиторий публичный:

```bash
git clone https://github.com/RocketRn/family-cookbook.git ~/family-cookbook
cd ~/family-cookbook && git checkout claude/zen-brown-nifiv3
```

### 9.5. Файл настроек `.env` (здесь и только здесь секреты)

Эта команда создаёт файл и сразу вписывает в него два случайных пароля базы данных (вы их не увидите, и это нормально):

```bash
cd ~/family-cookbook/deploy/gcp && cp -n .env.example .env && chmod 600 .env
sed -i "s/^POSTGRES_PASSWORD=CHANGE_ME$/POSTGRES_PASSWORD=$(openssl rand -hex 24)/; s/^API_DB_PASSWORD=CHANGE_ME$/API_DB_PASSWORD=$(openssl rand -hex 24)/" .env
```

Теперь откройте файл в простом редакторе:

```bash
nano .env
```

Стрелками перейдите к каждой строке с `CHANGE_ME` или с примером и впишите своё значение после `=`, без пробелов и кавычек:

| Строка                                 | Что вписать                                              |
| -------------------------------------- | -------------------------------------------------------- |
| `DOMAIN=`                              | `family-cookbook-4821.duckdns.org` (без `https://`)      |
| `BOT_TOKEN=`                           | токен от BotFather (раздел 8)                            |
| `BOT_USERNAME=`                        | username бота без `@`                                    |

### 9.7. Проверка хранилища фото

Проверочная программа записывает в ведро фото несколько тестовых файлов, читает их, открывает по временной ссылке и удаляет. В первый раз она собирается 10–20 минут.

```bash
cd ~/family-cookbook/deploy/gcp && docker compose run --rm s3check
```

В конце должно быть `Tests  2 passed`. Если видите `AccessDenied` или `SignatureDoesNotMatch`, проверьте `S3_BUCKET`, ключи и роль из раздела 5.2.

#### Что проверить именно на Google Cloud Storage

Google Cloud Storage понимает «язык» S3, но не целиком. Приложение уже настроено под него, и эти настройки проверяются тестами. Ниже — как убедиться, что настройки на месте, и что делать, если что-то не так.

**Настройки, без которых фото не работают:**

- `S3_REGION: auto` — Google ждёт именно `auto`, а не `us-east-1`.
- `S3_FORCE_PATH_STYLE: 'true'` — адрес фото вида `storage.googleapis.com/ведро/файл`.
- `AWS_REQUEST_CHECKSUM_CALCULATION: WHEN_REQUIRED` и `AWS_RESPONSE_CHECKSUM_VALIDATION: WHEN_REQUIRED` — не отправлять Google контрольные суммы, которые он не принимает. Эта настройка есть и в самой программе; строки в `compose.yml` — вторая страховка.

Все четыре строки уже записаны в `compose.yml` (не в `.env`), поэтому случайно их не потерять. Проверить, что сервер их видит:

```bash
cd ~/family-cookbook/deploy/gcp && docker compose config | grep -E "S3_REGION|S3_FORCE_PATH_STYLE|AWS_RE"
```

Должно быть восемь строк: по две каждого вида (для `api` и `worker`), со значениями `auto`, `"true"` и `WHEN_REQUIRED`.

**После первого фото** (раздел 10) посмотрите в журнал:

```bash
cd ~/family-cookbook/deploy/gcp && docker compose logs api worker | grep -iE "checksum|InvalidArgument|NotImplemented|BadDigest|SignatureDoesNotMatch|XAmzContent"
```

Пустой ответ — всё хорошо.

| Признак                                                                                                                                 | Причина                                                                                                     | Что делать                                                                                                                                                      |
| --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Фото не загружается, в журнале `api` есть `x-amz-checksum`, `InvalidArgument`, `BadDigest` или `XAmzContentSHA256Mismatch`              | Программа отправила Google контрольную сумму, которую он не принимает (обычно — старая версия кода)         | Обновите код (раздел 12, «Обновить приложение») и выполните проверку выше: должно быть `WHEN_REQUIRED`. Затем `docker compose run --rm s3check`.                |
| Фото загрузилось, но в приложении вместо него серый квадрат; если открыть ссылку на фото в браузере — `SignatureDoesNotMatch` или `403` | Неверный регион или «вид адреса»: `S3_REGION` не `auto` или `S3_FORCE_PATH_STYLE` не `'true'`               | Проверьте командой выше. Если в `compose.yml` что-то изменено вручную, верните: `git checkout deploy/gcp/compose.yml`, затем `docker compose up -d api worker`. |
| В журнале `worker` при уборке старых фото: `NotImplemented`                                                                             | Google не умеет удалять много файлов одним запросом; программа удаляет по одному (старая версия кода — нет) | Обновите код (раздел 12, «Обновить приложение»).                                                                                                                |
| `NoSuchBucket`                                                                                                                          | В `.env` неверное имя ведра                                                                                 | `nano .env`: `S3_BUCKET` — точно как в разделе 5.1, без `gs://` и пробелов. Затем `docker compose up -d api worker`.                                            |
| `AccessDenied`                                                                                                                          | У аккаунта ключа нет прав на ведро                                                                          | Раздел 5.2: роль **Storage Object User** у `cookbook-photos` на ведре фото.                                                                                     |

## 11. Резервные копии и проверка восстановления

- **Каждую ночь в 03:30 UTC** сервер сохраняет базу данных в ведро копий. Журнал: `cat ~/cookbook-backup.log`.
- Старше 30 дней копии удаляются сами (правило из раздела 5.4).
- Фото не копируются: они хранятся в Cloud Storage, где Google сам держит их в нескольких копиях. Удалённые файлы ещё 7 дней можно восстановить (soft delete).

**Проверка восстановления раз в месяц** (данные приложения не трогает):

```bash
cd ~/family-cookbook/deploy/gcp && ./restore-test.sh
```

Программа берёт последнюю копию, восстанавливает её во временную базу рядом с настоящей, сравнивает число пользователей, книг и рецептов, удаляет временную базу и пишет `Restore test OK`.

**Настоящее восстановление** (если данные испорчены):

```bash
cd ~/family-cookbook/deploy/gcp && ./restore.sh
```

Программа спросит подтверждение (нужно ввести `YES`), остановит приложение, восстановит последнюю копию и запустит приложение снова. Конкретная копия: `./restore.sh gs://<ведро>/db/cookbook-2026-10-09T0330Z.dump`. Список копий: `gcloud storage ls gs://<ведро>/db/`.

**Переезд на новый сервер:**

1. Создайте сервер по разделам 6 и 9: шаги 9.1–9.6, без 9.8.
2. Запустите только базу: `docker compose up -d postgres && docker compose run --rm migrate`.
3. Восстановите копию: `./restore.sh`.

## 12. Обновление, откат и остановка

**Обновить приложение** (когда я сообщу о новой версии):

```bash
cd ~/family-cookbook && git pull && cd deploy/gcp && docker compose up -d --build
```

Изменения в базе применяются сами, при запуске. Перед обновлением полезно сделать копию: `./backup.sh`.

**Откатиться на предыдущую версию:**

```bash
cd ~/family-cookbook && git log --oneline -5
```

Найдите в списке нужную версию (первые 7 знаков). Затем:

```bash
git checkout <7 знаков> && cd deploy/gcp && docker compose up -d --build
```

Если новая версия уже изменила базу, старая может с ней не работать. Тогда восстановите копию, сделанную до обновления (`./restore.sh`).

**Остановить только приложение** (данные остаются, сервер работает):

```bash
cd ~/family-cookbook/deploy/gcp && docker compose down
```

Запустить снова: `docker compose up -d`.

**Выключить сервер** (чтобы он не стоил денег):

1. Консоль → **Compute Engine → VM instances**.
2. Отметьте `cookbook` и нажмите **Stop**.

Пока сервер выключен:

- сам сервер **не оплачивается**;
- внешний адрес (Ephemeral) освобождается и **не оплачивается**;
- **оплачивается диск**: 20 ГБ Standard — это 0 USD в бесплатном регионе США (до 30 ГБ) и около 0,9 USD в месяц в Европе;
- **оплачиваются ведра**: на копейки.

Включить: **Start**. Через 1–2 минуты приложение запустится само, а DuckDNS получит новый адрес. Таймеры, которые закончились, пока сервер был выключен, пришлют сообщения при запуске (с опозданием).

**Удалить всё** (если проект больше не нужен):

1. Удалите сервер (**Delete** в списке VM).
2. Удалите оба ведра в Cloud Storage.
3. Закройте проект: **IAM & Admin → Settings → Shut down**.

После этого расходов нет.
